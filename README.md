# Tailor

Оболочка для установленного SEGGER J-Link Commander: Qt 6 Widgets / C++20.
Тёмная тема, MDI и платформенное оформление перенесены из Spotty; сам Spotty не изменяется.

## Сборка и запуск

Нужны CMake 3.24+, Qt 6.8+ (Widgets, Svg, Test) и компилятор C++20.

В VS Code доступны задачи **Tailor: Build Debug**, **Build Release**, **Test**
и **Package Release** (Terminal → Run Task). Сборка Debug назначена задачей
по умолчанию для `Ctrl+Shift+B` / `Cmd+Shift+B`. Тесты сначала собирают Debug;
пакет сначала собирает Release и запускает тесты, затем устанавливает результат
в `dist/release`. Установка не очищает уже существующий каталог.

Основные настройки находятся в `CMakePresets.json`. Пресеты работают из корня
проекта на Windows, macOS и Linux:

```sh
cmake --preset debug
cmake --build --preset debug --parallel 4
ctest --preset debug

cmake --preset release
cmake --build --preset release --parallel 4
ctest --preset release
cmake --build --preset release --target install --parallel 4
```

Сборки размещаются в `build/presets/debug` и `build/presets/release`.
Для macOS также доступны пресеты `debug-macos-arm64`, `release-macos-arm64`,
`debug-macos-x86_64` и `release-macos-x86_64`: используйте одно имя для
configure, build и test. Для другой архитектуры нужны совместимые компилятор
и библиотеки Qt; пресеты не устанавливают кросс-тулчейн.

Qt выбирается стандартным поиском CMake или через `CMAKE_PREFIX_PATH`:
`cmake --preset debug -DCMAKE_PREFIX_PATH=/path/to/Qt`. Машинные настройки
можно хранить в `CMakeUserPresets.json`, который исключён из Git. На macOS
задачи VS Code и архитектурные пресеты выбирают SDK через `CMAKE_OSX_SYSROOT=macosx`; при конфликте
SDK в терминале передайте `cmake --preset debug -DCMAKE_OSX_SYSROOT=macosx`
или путь к совместимому SDK. При перекрёстной сборке тесты можно запускать
только на совместимой машине.

Существующие сценарии `scripts/build.cmake`, `scripts/test.cmake` и
`scripts/package.cmake` остались как обёртки над пресетами. Они принимают
`TAILOR_CONFIG`, `TAILOR_QT_PREFIX`, `TAILOR_JOBS`, а на macOS также
`TAILOR_ARCH` и `TAILOR_OSX_SYSROOT`:

```sh
cmake -P scripts/test.cmake
cmake -DTAILOR_ARCH=arm64 -P scripts/package.cmake  # macOS
```

На Windows запускайте задачи из среды с настроенным компилятором (например,
Developer Command Prompt для MSVC); каталог `bin` соответствующей сборки Qt
должен быть в `PATH` для запуска тестов.

Альтернативный ручной запуск CMake:

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DCMAKE_PREFIX_PATH=/path/to/Qt
cmake --build build --config Release --parallel
ctest --test-dir build -C Release --output-on-failure
cmake --install build --config Release --prefix dist
```

При такой ручной сборке на macOS приложение находится в `build/tailor.app`, на Windows — `build/Release/tailor.exe`.
При конфликте Command Line Tools и Xcode явно передайте `-DCMAKE_OSX_SYSROOT=/path/to/compatible/MacOSX.sdk`.
Для ASan/UBSan используйте `-DTAILOR_SANITIZE=ON` с Clang/GCC.

## Использование

1. Установите SEGGER J-Link Software and Documentation Pack. В настройках проверьте путь к Commander.
2. Выберите USB и серийный номер либо Remote Server и строку подключения `host:port` / SEGGER tunnel string.
3. Загрузите список МК кнопкой «Список МК», выберите МК, SWD/JTAG и частоту в кГц.
4. Откройте HEX или BIN. Для BIN явно проверьте базовый адрес. HEX сохраняет адреса и промежутки между сегментами.
5. One Click Prog (F5) подключает target, при необходимости снимает защиту, стирает выбранным способом, пишет и проверяет через LoadFile, затем сбрасывает и запускает МК, если включено в настройках.

Отдельно доступны подключение, запись, проверка, полное стирание, сброс и запуск.
«Чтение памяти» читает адресный диапазон в отдельный буфер; его можно сохранить в BIN/HEX.
«Выбрать секторы» позволяет считать несколько, в том числе несоседних, секторов. Адреса сохраняются; разреженный буфер можно экспортировать только в HEX. Разметка реализована для STM32F101/F102/F103 (плотности 64–512 КиБ), STM32F405/F407 и GD32F405/F407 (512 КиБ и 1 МиБ), а также GD32F450 (512 КиБ, 1, 2 и 3 МиБ). Для остальных устройств используйте ручной диапазон. Источники: [ST RM0008](https://www.st.com/resource/en/reference_manual/rm0008-stm32f103xx-advanced-armbased-32bit-mcus-stmicroelectronics.pdf), [ST RM0090](https://www.st.com/resource/en/reference_manual/rm0090-stm32f405-415-stm32f407-417-stm32f427-437-and-stm32f429-439-advanced-armbased-32bit-mcus-stmicroelectronics.pdf), [GD32F4xx User Manual Rev 3.4](https://www.gd32mcu.com/data/documents/userManual/GD32F4xx_User_Manual_Rev3.4.pdf).
Для GD32F450 с 1 МиБ в пресете нужно вручную выбрать Single или Dual bank в соответствии с фактическим битом DBS в option bytes. Пока выбор не сделан, разметка секторов не показывается. Этот выбор влияет только на отображение и диапазоны чтения: программа не проверяет и не изменяет DBS. Названия банков и секторов предполагают, что перестановка банков FMC_SWP не включена; проверьте состояние устройства перед использованием.
Длину чтения можно вводить десятичным числом или в HEX с префиксом `0x`; суффиксы `k`/`K` и `m`/`M` означают 1024 и 1048576 байт соответственно (например, `64K` или `0x10K`).
По умолчанию адрес и длина чтения берутся из каталога Flash выбранного МК. Если каталог не задаёт единый непрерывный диапазон, адрес и длину нужно указать вручную.
В HEX-просмотре по умолчанию показан весь буфер; можно выбрать сектор, искать HEX-байты или печатный ASCII-текст с учётом регистра и переходить по адресу. Файл сравнения выравнивается с буфером по адресам, различия подсвечиваются, прокрутка синхронизирована. Для сравнения BIN используется установленный базовый адрес. Избранные пресеты сохраняют устройство, интерфейс, скорость, подключение и адрес BIN.
В HEX-просмотре выберите сектор или страницу в списке View и нажмите «Прочитать страницу»: данные будут считаны из МК в рабочий буфер. Для чтения нескольких секторов используйте «Выбрать секторы» на вкладке прошивки.
Двойной щелчок или F2 на HEX-байте открывает редактирование: введите две шестнадцатеричные цифры и нажмите Enter. Меняется рабочий буфер, используемый при программировании; сохраните его кнопкой «Сохранить буфер». Несохранённые изменения отмечены звёздочкой; перед заменой буфера и закрытием программы запрашивается подтверждение.
Последний выбранный избранный пресет и состояние Unlock восстанавливаются при запуске. Если для текущего МК или установленного J-Link разблокировка недоступна, галочка сбрасывается. При прошивке с Unlock по-прежнему требуется подтверждение возможного стирания.
В информации о буфере отображается контрольная сумма; алгоритм выбирается в настройках: MD5 (по умолчанию), CRC-32/Ethernet или SHA-256. Сумма вычисляется по байтам сегментов в порядке адресов, без заполнения промежутков и без включения адресов.

Журнал ограничен последними 10000 строками и экспортируется в текстовый файл. Индикатор показывает процент текущего этапа, когда его сообщает J-Link; для этапов без процента отображается неопределённый прогресс. Процент этапа не является процентом всей операции.
Статусы J-Link и target относятся к последней проверке: постоянного опроса устройства нет, поскольку он может мешать другому ПО. CLI-сессия освобождается после операции.

## Ограничения и поведение

- Программа не поставляет SEGGER и не заменяет драйверы. Возможности определяет установленный пакет и программатор.
- STM32 Unlock использует только старую `JLinkSTM32Exe` / `JLinkSTM32.exe`. Нужно выбрать подходящее семейство в настройках. Утилита снята SEGGER с поддержки; интеграция нового Device Provisioner ещё не реализована. При отсутствии утилиты запись с Unlock блокируется. Снятие защиты стирает флеш и может сбросить option bytes; неподдающиеся обратному снятию уровни защиты не обходятся.
- Верификация при записи выполняется загрузчиком SEGGER (`LoadFile`). Отдельная проверка использует `VerifyBin` по сегментам и требует, чтобы память была доступна для чтения; внешняя QSPI может требовать предварительной инициализации.
- «Затронутые секторы» означает политику загрузчика SEGGER. Данные вне файла в стираемом секторе не считаются сохранёнными. При необходимости предварительно считайте резервную копию.
- Отмена/таймаут останавливают процесс на ПК. Флеш может оказаться частично записанной; состояние target после этого неизвестно.
- Максимальный размер входного BIN/HEX-файла и чтения — 256 MiB. HEX-просмотр показывает только существующие сегменты, не заполняя промежутки.
- Linux ARM означает ARM64; 32-битные ARM/x86 не входят в текущую сборочную матрицу.
- По умолчанию используется английский язык; русский можно выбрать в настройках. Язык меняется после перезапуска. Вывод SEGGER и технические ошибки остаются на английском.

## Ассоциации файлов

macOS: типы `.hex`/`.bin` объявлены в bundle; выберите Tailor через «Открыть с помощью».
Linux: при установке добавляются desktop/MIME-файлы; при необходимости обновите системные базы desktop/MIME.
Windows: выполните `packaging/register-windows.ps1 -Executable C:\path\tailor.exe`, затем выберите Tailor в «Открыть с помощью». Скрипт регистрирует приложение для текущего пользователя без принудительной смены программы по умолчанию.
Открытие файла никогда само по себе не запускает прошивку.

## Проверки

QtTest покрывает Intel HEX (контрольные суммы, адреса, перекрытия, переход границы 64 KiB), параметры CLI, ошибки при нулевом exit code, чтение, отмену и каталог МК с подставным CLI. UI-тест открывает настройки и BIN. CI подготовлен для Windows x64, macOS arm64/x64, Linux x64/arm64; результаты удалённого CI требуют запуска в GitHub.

Полезные следующие дополнения: сравнение буфера с файлом, автоматическая резервная копия перед стиранием, экспорт/импорт пресетов и отчёт о прошивке с полным SHA-256.
